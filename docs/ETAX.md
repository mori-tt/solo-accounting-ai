# ETAX.md

e-Tax(国税電子申告・納税システム)連携の実現可否調査(Issue #135)。
結論と根拠、代替手段を記録する。2026-11-02時点の公開情報に基づく。

## 結論

**本アプリ単体(ブラウザアプリ+Firebase)での e-Tax 申告送信は現時点では実装不可。**

## 調査結果

### 公開されている連携手段

| 手段 | 内容 | 申告送信に使えるか |
|---|---|---|
| 国税電子申告・納税システムAPI | HTTPベースのAPI。e-Tax登録済みの基本情報(氏名・住所等)や各税目情報、受信データ(xtx)の参照を返却 | **不可**。API仕様は参照系のみ。公式ページ明記「認証(ログイン)や申告等データ送信など、API一覧に記載がない操作については対応していません」 |
| 受付システムインターフェイス仕様書 | 申告等データの送信プロトコル仕様(e-Tax仕様書一覧 項番2) | 理論上は可能だが下記制約あり |
| 送受信モジュール/電子署名モジュール/CSV変換モジュール仕様書 | e-Taxソフト相当のクライアントモジュールIF | デスクトップ/ローカルコンポーネント前提 |
| マイナポータル等連携プラットフォームAPI | 控除証明書等データをマイナポータルから取得するAPI(仕様公開は審査制・10営業日程度) | 送信ではなく証明書データ取得の補助 |

### 申告送信に必要なもの(受付システムIF経由)

1. **電子署名(電子証明書)が必須**: 申告データには利用者の電子署名が必要。
   マイナンバーカード(署名用電子証明書)または税務署発行の電子証明書。
   ブラウザアプリ単体ではICカードへアクセスする手段がなく、署名には
   ローカルの署名コンポーネント(JPKI利用者ソフト・電子署名モジュール相当)
   が必要になる。サーバーサイドで他人の署名を代行することもできない
   (署名は本人の秘密鍵で行うため)。
2. **帳票XMLの生成**: 「XML構造設計書及び帳票フィールド仕様書」(所得税関係だけで
   約8MBの仕様書)と「手続一覧・手続内帳票対応表・対象帳票一覧」に基づく
   申告書データの生成が必要。対応帳票は膨大。
3. **利用者識別番号・開始届出**: エンドユーザがe-Taxの利用者識別番号を
   取得し、電子証明書の登録(開始届出書)を済ませていることが前提。
4. **APIキー**: 参照系APIでも専用メールアドレスへの発行申請が必要。

### 実際の会計ソフトの状況

freee・マネーフォワード等が行う e-Tax 送信は、上記の受付システムIF仕様に
基づく自前実装+電子署名まわりのローカル/外部連携を組み合わせた大規模対応であり、
本アプリのスコープ(個人事業主向け経理・申告準備)とは段違いの投資が必要。

## 代替手段(現行機能で提供可能)

| 手段 | 状態 |
|---|---|
| `/reports/filing` 収支内訳書・青色申告決算書の集計画面 | 実装済み。確定申告書等作成コーナーへの転記用 |
| 取引CSV出力・JSONバックアップ | 実装済み。税理士・他ソフトへのデータ受け渡し |
| 証憑一覧CSV・監査ログCSV | Issue #135で追加。調査対応・添付資料として利用可 |

### 導線としての選択肢

- **確定申告書等作成コーナー(国税庁)**: 集計値の転記で個人の申告は完結する。
  本アプリの位置づけは「申告準備(集計・証憑管理)」であり、REQUIREMENTS.mdの
  スコープ外記載(確定申告書の直接作成・e-Tax連携)と整合する。
- **税理士連携**: CSV/バックアップを税理士へ渡し、送信は税理士側のソフトで行う
- **e-Tax送信対応ソフトへの移行**: freee等へCSVインポートする導線

## 中長期の検討余地

- マイナポータル等連携PF API(控除証明書データ取得)は申告準備の補助として
  有望だが、仕様公開申請・審査・連動テストが必要で別Issueでの検討とする
- xtx(申告書等データ)出力は帳票仕様対応が前提。需要が明確になった場合に
  帳票単位で段階対応を検討
