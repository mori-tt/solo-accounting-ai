# ELECTRONIC_BOOKKEEPING.md

電子帳簿保存法(電帳法)の要件と本アプリの対応状況の整理(Issue #135)。
根拠: 国税庁「電子帳簿保存法一問一答」・施行規則第4条(電子取引)、第5条(スキャナ保存)、
法第4条(国税関係帳簿書類の電磁的記録による保存)。2026-11時点の公開情報に基づく。

## 対象スコープの整理

| 区分 | 本アプリでの対象 |
|---|---|
| 電子取引の取引情報(受領した請求書・領収書等の電磁的記録) | `receipts` コレクション + Storage上の証憑ファイル |
| 国税関係帳簿(仕訳帳・総勘定元帳等) | `transactions` → domain/ledger.ts が計算する仕訳帳・総勘定元帳・月次集計 |
| スキャナ保存(紙で受領した証憑の電子化) | 対象外(本アプリは紙証憑のスキャン保存制度の承認取得を支援しない) |

## 要件ごとの対応状況

### 1. 検索機能の確保(可視性)

要件: 電子取引データは **取引年月日・取引金額・取引先** で検索できること
(範囲指定・2項目以上の組合せ検索要)。

| 対象 | 実装 | 状況 |
|---|---|---|
| 取引(帳簿側) | `/search` で期間指定 + 摘要/取引先/科目/金額の横断検索(確定済み取引) | 対応済み(既存) |
| 証憑(電子取引側) | `/receipts` で取引日範囲・キーワード(取引先・ファイル名・金額)検索。証憑メタデータ(`transactionDate`/`amount`/`counterparty`)と紐付取引の両方を対象 | **本Issueで追加** |

備考: 「2課税年度前の売上高5,000万円以下」または「日付・取引先ごとの整理」が
ある事業者は、税務調査時の「ダウンロードの求め」に応じられれば検索機能自体は
不要とされる。本アプリの想定ユーザー(個人事業主・小規模事業者)は多くが
この例外に該当しうるが、検索機能自体は利便性のため提供する。

### 2. 訂正削除履歴(真実性)

要件: 次のいずれか — タイムスタンプ付与後の授受 / 速やかなタイムスタンプ付与 /
訂正削除ができない又は履歴を確認できるシステムでの授受・保存 /
訂正削除防止の事務処理規程の運用。

| 実装 | 状況 |
|---|---|
| `auditLogs` コレクションが append-only(firestore.rules で update/delete を拒否)。登録・更新・削除・締め・AI提案の承認/却下・インポートを actorUid + targetPath + createdAt で記録 | 対応済み(既存) |
| `/audit-log` で期間・操作・対象種別による絞り込みと CSV エクスポート | CSV エクスポートは**本Issueで追加** |

備考: 監査ログは識別情報のみを記録し内容スナップショットは保存しない
(docs/SECURITY_RULES.md)。「訂正削除履歴を確認できるシステム」としては
誰が・いつ・どのドキュメントを・どう操作したかが確認できる設計。
厳密な時刻認証タイムスタンプは付与していないが、上記システム要件は
認定タイムスタンプとは別の代替措置として法令上認められる。

### 3. タイムスタンプ

| 実装 | 状況 |
|---|---|
| 各ドキュメントの `createdAt`/`updatedAt` を Firestore Timestamp で保存。監査ログは serverTimestamp(request.time 検証: 現在時刻±1hのみ許可) | 対応済み(既存) |

備考: 認定タイムスタンプ(時刻認証局発行)ではなくシステム時刻。
訂正削除履歴を確認できるシステムとしての措置でカバーする(2.参照)。

### 4. 可視性の確保(その他)

| 要件 | 実装 | 状況 |
|---|---|---|
| 見読可能装置 | Webアプリ(ブラウザ)。証憑画像/PDFの表示・取引一覧の表示・印刷(レポート画面) | 対応済み(既存) |
| ダウンロードの求め | JSONバックアップ(全コレクション)/取引CSV/証憑一覧CSV/監査ログCSV/証憑ファイルの個別ダウンロード(GET /api/receipts/[id]) | 証憑・監査ログのCSVは**本Issueで追加** |
| システム概要書(自社開発システムの場合) | 本ドキュメント + docs/FIRESTORE_SCHEMA.md + docs/SECURITY_RULES.md が相当 | 対応済み |

### 5. 優良電子帳簿(過少申告加算税5%軽減)の追加要件

「優良」な電子帳簿として認められるには訂正削除履歴の確保・相互関連性・
検索機能(取引年月日・勘定科目・取引金額)・すべての国税関係帳簿の備付け等が必要。
本アプリは仕訳帳・総勘定元帳の出力(レポート)・検索を持ち要件の多くを満たすが、
「すべての国税関係帳簿の備付け」(合計残高試算表等の範囲)や届出・運用面の
確認が必要であり、優良電子帳簿としての認定取得支援は現状スコープ外。

## 残ギャップ・今後の検討事項

- 証憑ファイルの一括ダウンロード(zip等): 現状は個別ダウンロード+一覧CSV。
  一括取得が必要になった場合は別Issueで検討
- 証憑メタデータは紐付け時点の取引値のスナップショット。
  取引側を後で編集しても自動追従しない(検索は双方の値を対象とするため
  探索可能性は維持される)
- タイムスタンプの認定時刻認証サービス(PAdES等)への移行は未対応。
  現行は「訂正削除履歴を確認できるシステム」としての措置で対応
